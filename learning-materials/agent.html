3概念解释 Concept Explanation

一句话定义

Agent（行为体 / 智能体）是指能够感知其所处环境、并根据感知做出决策、进而对环境施加行动的存在——它不是一个被动回答问题的工具，而是一个"能办事"的行动者。

通俗类比

想象一个快递配送员：他（1）读取包裹面单和路况（感知）；（2）判断走哪条路线最省时（决策）；（3）真的骑车出发、送货、签收（行动）。一个只会在聊天里告诉你"配送大概 2 小时"的客服机器人，不是 Agent；而那个会看路、选路、改路、最终把货送到的配送员，才像 Agent。Agent 的关键词是 act / to do（行动）。

权威定义

这一术语有两条公认的、来自权威体系的定义线索：

① 学术教科书定义（智能体范式）
在人工智能领域的经典教科书《人工智能：现代方法》（Stuart Russell 与 Peter Norvig 著）中，agent 被定义为"通过传感器感知环境、并通过执行器对环境影响行动"的实体；AI 被理解为"对从环境中接收感知、并执行行动的动作体的研究"。这是现代 AI 的统一范式。该教材被全球 1500 多所院校采用，是引用最广的 AI 教材。

② 官方政策定义（面向大模型时代的智能体）
2026 年 5 月，国家网信办、国家发展改革委、工业和信息化部联合印发的《智能体规范应用与创新发展实施意见》将智能体定义为"具备自主感知、记忆、决策、交互与执行能力的智能系统，是人工智能产品及服务的重要形态"。五个能力关键词——感知、记忆、决策、交互、执行——精确对应了当前智能体的核心技术要素。

术语说明："Agent"的中文译名尚未完全统一，常见的译法包括"智能体""行为体""代理/代理人"。学术界有学者主张译为"行为体（doer/actor）"，因为其本义指"能行动、行使能力者"，"智能体"的说法容易让人误以为它"天然自带智能"。理解时抓住"行动者"这一核心即可，不必在译名上纠结。

4核心机制 Core Mechanism

4.1 经典框架：Agent 与环境

所有 Agent 共享同一个最基本结构——它通过传感器（sensors）接收来自环境的输入（称为感知 percept），内部做决策，再通过执行器（actuators）对环境影响行动。把"感知序列 → 行动"的映射记作 agent function（Agent 函数）。

环境（Environment）
↑ 感知 ←─────── Agent ───────→ ↓ 行动
传感器(感知层)　决策机制(大脑)　执行器(行动层)

4.2 理性 Agent：什么算"聪明"

Russell & Norvig 提出理性 Agent（rational agent）：它针对每个可能的感知序列，做出能最大化其期望性能度量（expected performance measure）的行动。要特别注意，这里的"理性"有三个重要边界，是常被误读的地方：

  • 理性 ≠ 全知（omniscient）：它并不事先知道一切，因此结果仍可能出错。
  • 理性 ≠ 全知 ≠ 永远成功：它只对"在给定信息下选最优"负责，无法保证实际效果完美。
  • 理性包含"主动获取信息"：不知道时先去查证，而不是装作知道——这对应了现代 Agent 的工具检索行为。

4.3 当代机制：LLM 驱动的 Agent（ReAct 循环）

大语言模型（LLM）成为 Agent 的"大脑"后，工程上最主流的运行模式是ReAct（Reasoning + Acting，推理 + 行动）循环，由 Google 研究团队在 2022 年的论文中提出。它的核心是让模型在"思考—行动—观察"间反复迭代，直到任务完成：

  1. Thought（思考）：模型理解当前状态，判断还缺什么、下一步该做什么。
  2. Action（行动）：模型发出结构化指令，调用某个工具（tool）——查天气 API、执行代码、读文件、发邮件等。
  3. Observation（观察）：系统执行工具并返回结果，作为新的感知注入上下文。
  4. 回到第 1 步循环，直到模型判定目标达成，或触发终止条件（如最大步数、超时、预算上限）。

从"纯粹生成一段话回答你"变成"为了回答问题而真的去查、去做、去验证"，这是 Agent 相对普通聊天机器人的质变——从"我觉得"变成"我查了、我做了"。

4.4 现代 Agent 的组成模块

综合 Anthropic 官方文档与多份工程综述，现代 LLM Agent 通常可拆成五个组件，可用"大脑—规划—记忆—双手—护栏"来记忆：

组件职责实现要点
模型核心
(LLM)		推理与决策大脑理解输入、决定下一步（选工具/作答/求助）
规划拆解目标、排定步骤ReAct（边想边做）、Plan-and-Execute（先规划再执行）、动态重规划
记忆跨轮次保持上下文工作记忆/短时（会话上下文）、长时（向量库/知识图谱持久化）
工具影响外部世界Function Calling / Tool Use；MCP（模型上下文协议）统一接入
控制与护栏防止失控最大迭代次数、超时、成本上限、工具白名单、人工审批

4.5 一个关键架构区分：Workflow vs Agent

Anthropic《Building Effective Agents》官方指南指出，业界常把两者混称，但架构上有重要区别：

Workflow（工作流）：LLM 与工具沿着预定义的代码路径被编排的系统。路径是写死的，只是每一步内部可由模型做决策。例如"先写大纲 → 检查通过 → 再成文"。

Agent（智能体）：LLM 动态决定自己的流程与工具使用，自己掌控"如何完成任务"。步骤数量、顺序事前无法预知。

进阶工作流模式还包括：提示链（Prompt Chaining）、路由（Routing）、并行化（Parallelization）、协调者-执行者（Orchestrator-Workers）、评估器-优化器（Evaluator-Optimizer）。理解它们有助于判断该用哪种结构。

5应用场景 Applications

场景 A：客户支持智能体

  • 怎么用：不只"聊天"，还通过工具查询客户订单、调用系统发放退款或更新工单。
  • 为何有效：有明确成功标准（问题是否解决），可程序化核对、收集反馈迭代，并允许人类介入。

场景 B：编码智能体（Coding Agent）

  • 怎么用：模型自主修改多个文件、跑测试，把报错当作"观察"继续修正。
  • 为何有效：自动测试给出客观反馈，问题是结构化的、可验证的，Agent 能围绕测试结果迭代（如 SWE-bench 任务）。

场景 C：多步骤/研究类智能体

  • 怎么用：一个主智能体把研究任务拆给多个子智能体并行检索，再汇总成带引用的报告。
  • 为何有效：相比一次性 RAG 检索，多步动态搜索能适应新发现、交叉验证，产出更高质量结果。

场景 D：面向执行结果的企业自动化

  • 怎么用：在可信环境中，把"做事的人"从流程中解放出来——由 Agent 直接跑通流程、处理合规/客服等结构化任务。
  • 为何有效：从"做对事情"走向"做成对的事"，交付更快、更可问责（前提：做好沙盒、护栏与人工监督）。

6易混淆问题 Confusions

易混概念区别要点
Chatbot（聊天机器人）
vs
Agent		 Chatbot 主要生成回答，边界通常在"对话"内；Agent 要为达成目标而采取一连串行动，调用工具、影响环境并对结果负责。能聊天 ≠ 是 Agent。
Workflow（工作流）
vs
Agent		 Workflow 的路径由代码预定义，可预测、稳定；Agent 的路径由模型动态决定，灵活但成本更高、更易出错。多数任务用 Workflow 或更简单方案即可，不必都上 Agent。
Agent（泛 AI 术语）
vs
LLM Agent（大模型智能体）		 "Agent"最早指任何能感知—决策—行动的实体（恒温器、机器人、软件都算）。LLM Agent 特指以大模型为决策大脑、通过推理规划调用工具的新形态。二者是"广义基座 + 当代具体形态"的关系。
"智能体"这个译名
（中译名争议）		 有学者认为 agent 本义是"行为体 / 行动者"，译"智能体"易暗示其天然智能。本文按主流沿用"智能体"，但理解上应抓住"它是行动者，智能由系统整体涌现"这一本质。

常见误区速查

  • 误区：Agent 越复杂越好。正解：Anthropic 强调"先从最简单的方案开始，能不加复杂度就不加"，Agent 以延迟和成本换性能，需权衡。
  • 误区：有记忆就是 Agent。正解：记忆只是组件之一，Agent 的核心是"自主决定流程并行动"。
  • 误区：理性 Agent 不会犯错。正解：理性 ≠ 全知 ≠ 成功，它只保证在信息约束下做最优选择。
